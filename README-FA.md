# راهنمای انتشار سایت «آگاهی حقوقی با اکبر امیری» روی Cloudflare (بدون ترمینال، بدون هزینه)

زمان لازم: حدود ۳۰ تا ۴۵ دقیقه. همه‌چیز از مرورگر انجام می‌شود.

## این پروژه چه دارد؟
- همهٔ صفحات قبلی (قوانین، جرایم و جزاها، ابزارها، خدمات، اسناد، پرسش‌ها) با همان طراحی.
- حساب کاربری واقعی (ثبت‌نام/ورود/خروج، رمز رمزنگاری‌شده، نشست امن).
- ثبت درخواست خدمت با شمارهٔ پیگیری، آپلود فایل (PDF/JPG/PNG)، وضعیت درخواست، اعلان‌ها.
- پنل مدیریت در آدرس `/admin/` (کاربران، درخواست‌ها، فایل‌ها، اعلان، پرسش‌ها، تنظیمات تماس، گزارش رویدادها).
- سایت یک Worker واحد است: صفحات + API + دیتابیس D1. هیچ هاست یا دامنه‌ای لازم نیست؛ آدرس شما چیزی شبیه
  `https://agahi-hoquqi.نام‌شما.workers.dev` خواهد بود.

---

## مرحلهٔ ۱ — ساخت حساب‌ها (رایگان)
1. در https://github.com ثبت‌نام کنید (اگر حساب ندارید).
2. در https://dash.cloudflare.com ثبت‌نام کنید. **کارت بانکی لازم نیست.**

## مرحلهٔ ۲ — بارگذاری فایل‌ها در GitHub
1. در GitHub: دکمهٔ سبز **New** → نام مخزن (Repository) مثلاً `agahi-hoquqi` → **Private** → **Create repository**.
2. فایل ZIP این پروژه را روی کامپیوتر **Extract** کنید.
3. در صفحهٔ مخزن: **uploading an existing file**. GitHub در هر بار بارگذاری حداکثر ۱۰۰ فایل می‌پذیرد، پس در ۴ نوبت بارگذاری کنید
   (هر نوبت: فایل‌ها/پوشه‌ها را با ماوس بکشید و رها کنید، پایین صفحه **Commit changes** را بزنید و دوباره **Add file → Upload files**):
   - **نوبت ۱:** همهٔ فایل‌ها و پوشه‌های بیرون از `public` (یعنی `src`، `scripts`، `tests`، `migrations`، و فایل‌های `wrangler.jsonc`، `package.json`، `README-FA.md`، `.gitignore`)، به‌علاوهٔ پوشهٔ `public/assets`. اگر از شما خواست، پوشهٔ `public` را بسازید؛ بهتر است خود پوشهٔ `public` را بکشید و بعد پوشهٔ `laws` را از داخل آن در نوبت‌های بعد اضافه کنید.
   - **نوبت ۲:** همهٔ بقیهٔ چیزهای داخل `public` **به‌جز** پوشهٔ `laws` (فایل‌های `index.html`، `404.html`، `sw.js` و … و پوشه‌های `account`، `admin`، `articles` و غیره).
   - **نوبت ۳:** نیمهٔ اول پوشه‌های داخل `public/laws` (پوشه‌های شمارهٔ ۱ تا ۶۰) و فایل `index.html` همان پوشه.
   - **نوبت ۴:** نیمهٔ دوم (پوشه‌های شمارهٔ ۶۱ به بعد).
   مهم: ساختار پوشه‌ها باید مثل ZIP بماند (پوشه‌ها را بکشید، نه تک‌تک فایل‌ها).
   پس از پایان، در صفحهٔ اصلی مخزن باید `public`، `src`، `migrations` و `wrangler.jsonc` را ببینید.

## مرحلهٔ ۳ — ساخت دیتابیس
1. در Cloudflare: منوی چپ **Storage & databases** → **D1 SQL database** → **Create database**.
2. نام: `agahi-hoquqi-db` → **Create**.
3. **Database ID** (یک رشتهٔ طولانی) را کپی کنید.
4. در GitHub فایل `wrangler.jsonc` را باز کنید → آیکن مداد (Edit) → عبارت `PUT-YOUR-DATABASE-ID-HERE` را با شناسهٔ کپی‌شده عوض کنید (گیومه‌ها بماند) → **Commit changes**.

جدول‌های دیتابیس **خودکار** هنگام اولین بازدید ساخته می‌شوند؛ لازم نیست چیزی در D1 اجرا کنید.

## مرحلهٔ ۴ — اتصال GitHub به Cloudflare و انتشار
1. در Cloudflare: **Workers & Pages** → **Create application** → **Import a repository** (یا Connect to Git).
2. حساب GitHub را وصل کنید و مخزن `agahi-hoquqi` را انتخاب کنید.
3. نام پروژه را `agahi-hoquqi` بگذارید (باید با `name` داخل `wrangler.jsonc` یکی باشد).
4. تنظیمات Build را دست نزنید (دستور Deploy: `npx wrangler deploy`). **Save and Deploy** را بزنید.
5. چند دقیقه صبر کنید تا «Success» ببینید. آدرس سایت در صفحهٔ همان Worker نشان داده می‌شود.

## مرحلهٔ ۵ — کد راه‌اندازی مدیر (مهم)
1. Cloudflare → Workers & Pages → پروژهٔ `agahi-hoquqi` → **Settings** → **Variables and Secrets** → **Add**.
2. نوع: **Secret** — نام: `ADMIN_SETUP_CODE` — مقدار: یک عبارت طولانی و محرمانهٔ خودتان (حداقل ۱۶ نویسه). **Deploy** را بزنید.
3. در سایت خودتان با شمارهٔ خودتان **ثبت‌نام** کنید.
4. به آدرس `/admin/` بروید (مثلاً `https://…workers.dev/admin/`) → کد بالا را وارد کنید → حساب شما «مدیر» می‌شود.
   این کار فقط یک بار و فقط وقتی هنوز مدیری وجود ندارد کار می‌کند. بعد از آن می‌توانید مقدار Secret را عوض یا حذف کنید.

## مرحلهٔ ۶ — شمارهٔ واتساپ و تلگرام (اختیاری ولی لازم برای دکمه‌ها)
- ساده‌ترین راه: در `/admin/` → تب «تنظیمات تماس» → شماره و نام کاربری را بنویسید → ذخیره.
- راه دیگر: فایل `public/config/contact.js` را در GitHub ویرایش کنید.
تا وقتی این مقادیر خالی باشد، دکمه‌های واتساپ/تلگرام به صفحهٔ «تماس با ما» می‌روند و خراب نمی‌شوند. من هیچ شماره‌ای از خودم نساخته‌ام.

## مرحلهٔ ۷ — آدرس برای گوگل و پیش‌نمایش لینک (اختیاری)
بعد از اینکه آدرس سایت مشخص شد: Settings → **Build** → **Variables and secrets** → **Add**:
`SITE_URL` = `https://آدرس-سایت-شما.workers.dev` (بدون / آخر). سپس یک بار **Deployments → Retry** یا یک تغییر کوچک در GitHub بدهید.
نقشهٔ سایت (`/sitemap.xml`) و `robots.txt` بدون این کار هم با آدرس درست ساخته می‌شوند.

## محدودیت‌های Free Tier (صادقانه)
| قابلیت | وضعیت | توضیح |
|---|---|---|
| صفحات سایت | رایگان | فایل‌های ثابت هزینه و سقف روزانه ندارند |
| API و ورود/ثبت درخواست | رایگان با سقف | Workers رایگان: حدود ۱۰۰٬۰۰۰ درخواست API در روز |
| دیتابیس D1 | رایگان با سقف | حدود ۵ گیگابایت کل، ۱۰۰٬۰۰۰ نوشتن در روز |
| ذخیرهٔ فایل | **داخل D1، حداکثر ۲ مگابایت برای هر فایل** | R2 بزرگ‌تر است ولی برای فعال‌سازی کارت بانکی می‌خواهد؛ طبق قول شما فعال نشد. اگر روزی خواستید: R2 را بسازید، با نام `FILES` به Worker وصل کنید؛ کد خودکار از آن استفاده می‌کند و سقف ۱۰ مگابایت می‌شود |
| دامنه | رایگان | آدرس `*.workers.dev` |
| ایمیل/پیامک تأیید | **ندارد** | سرویس رایگان مطمئنی برای پیامک نیست؛ بازیابی رمز فراموش‌شده فعلاً دستی است (مدیر می‌تواند راهنمایی کند) |

### نکتهٔ مهم دربارهٔ رمزنگاری رمز عبور
Worker رایگان سقف کوتاهی برای زمان پردازش (CPU) دارد و رمزنگاری رمز عبور سنگین است. من این کد را فقط در محیط آزمایشی خودم اجرا کرده‌ام، نه روی Cloudflare واقعی.
اگر هنگام ورود/ثبت‌نام در Cloudflare خطای «exceeded CPU» (کد ۱۱۰۲) دیدید: در Variables همین پروژه متغیر متنی `PBKDF2_ITERATIONS` را با مقدار `50000` بسازید (امنیت کمی کمتر ولی قابل‌قبول)، یا پلن Workers Paid (حدود ۵ دلار در ماه) را در نظر بگیرید — **بدون اجازهٔ شما فعال نمی‌شود.**

## اگر مشکلی پیش آمد
- «Database not found / D1»: مرحلهٔ ۳ را دوباره بررسی کنید (شناسهٔ درست؟ نام `agahi-hoquqi-db`؟).
- صفحهٔ سفید یا خطای ۵۰۰ در API: Cloudflare → پروژه → **Logs** را ببینید.
- بعد از هر تغییر در GitHub، Cloudflare خودکار دوباره منتشر می‌کند.
